# Code Engine — 代码工程规范

本 skill 管的是**代码结构的工程化规范**：哪些访问方式从一开始就禁止、经典模式组合在真实框架里怎么落地才不被代理/生命周期/全局状态反咬。
每条规范都来自真实项目的踩坑与重构，不是风格偏好。

## 核心原则（所有序列的共同前提）

1. **全局可达 ≠ 全局可直接访问。** 存储、连接、注册表这类天然全局的设施，只能经一个收敛的 API 出口访问，禁止业务代码在任意位置直接触碰。
2. **横切能力集中在一处实现，不靠业务"记得"。** 租户、权限、逻辑删除、审计、序列化这类规则，统一在出口层/拦截器层做；散落在业务里的实现必然漏。
3. **隐式通道必须生命周期受控。** 请求上下文（thread-local / ctx / async-local）只能在边界设置、在出口清理；绝不与全局对象或复用单元（线程/协程/连接池）的生命周期混同。
4. **框架负责装配，代码不自己逃逸。** 组件的收集、注册、生命周期交给容器/注册中心；禁止静态可变注册表 + 构造期自注册。
5. **fail-fast，不静默降级。** key 缺失/重复、泛型不可解析、配置缺失、上下文缺值，启动或请求即失败；静默兜底（降级 Object、后注册覆盖先注册、缺上下文就放行）会把问题推迟到线上。
6. **编译期能挡住的错误，不留给运行期反射。** 显式传类比反射猜类型可靠；反射只在框架装配侧集中使用。

## 总检查清单

- [ ] 每个存储设施在业务代码中零直接引用，只出现于它的 API 封装层
- [ ] SQL / 原生查询只存在于 Mapper/Repository 层，无跨层、跨域直查
- [ ] 横切规则（租户/权限/审计/序列化）在出口层统一生效，不依赖业务自觉
- [ ] 请求上下文只在边界设置、出口清理，清理在 finally/defer 且用 remove/clear
- [ ] 没有全局/静态/单例/池化对象持有请求上下文；异步传递靠显式捕获
- [ ] 出口层读上下文缺值时 fail-fast，不静默放行
- [ ] 没有静态可变注册表；策略由容器收集、在工厂内注册
- [ ] 泛型类型显式传入，或由工厂侧解析；没有构造器自解析泛型
- [ ] key 重复/缺失、泛型不可解析、配置缺失时启动直接失败，无静默覆盖与降级
- [ ] 策略/组件依赖全部显式注入（构造器注入或 ctx），无隐式全局取用
- [ ] Go：注册中心是包级泛型 `Registry`，组件 `init()` 只注册、无副作用，入口 blank import 集中触发
- [ ] Go：工厂同时提供原型 `New` 与单例 `Get`，单例缓存 key 含全部配置参数，有状态对象只用 `New`
- [ ] Go：ctx 只传配置不传实例，key 用空 struct 实例，缺配置返回 error 不 panic，且 `defer cancel()`
