# Intent Capture — 需求澄清与文档生成

## 触发条件

当用户说以下内容时触发：

- "生成文档"
- "整理需求"
- "明确目的"
- "整理意图"
- "描述问题"
- "整理现象"
- 任何要求澄清需求而非执行代码的请求

## 核心原则

**这是一个只整理、不执行的 skill。**

目标：与用户持续对话，通过选项和选择，明确以下三点：

1. **需要的效果和目的** — 用户想要达成什么？
2. **当前的问题和现象** — 现在有什么不对或不足？
3. **涉及的主题文件** — 哪些文件或模块与此相关？

## 对话流程

### Step 1: 识别需求类型

使用 AskUserQuestion 让用户选择或补充：

```
这个问题属于哪种类型？
- 新功能开发
- Bug 修复
- 优化改进
- 架构调整
- 其他（请补充）
```

### Step 2: 明确效果和目的

继续追问，让用户明确：

```
想要达成什么效果？
- [列出常见效果选项]
- 其他/补充
```

使用多选项让用户选择，同时允许用户补充。

### Step 3: 描述当前现象

```
当前是什么情况？
- [基于类型列出常见现象]
- 其他/补充
```

### Step 4: 识别涉及文件

```
涉及哪些文件或模块？
- [列出项目中的相关文件选项]
- 其他/补充
```

### Step 5: 生成整理文档

当收集足够信息后，生成结构化文档：

```markdown
# 需求整理

## 需求类型
[整理后的类型]

## 效果和目的
[整理后的目的描述]

## 当前问题和现象
[整理后的问题描述]

## 涉及的文件
- [文件列表]

## 补充说明
[其他重要信息]
```

## 对话策略

1. **使用选项而非自由输入** — 先提供选项让用户选择，再让用户补充
2. **重复调用直到清晰** — 必要时重复 Step 2-4
3. **不主动猜测** — 需要用户确认的信息不要替用户决定
4. **不执行任何代码** — 只整理，不修改

## 成功标准

- [ ] 明确了效果和目的
- [ ] 描述了当前现象
- [ ] 列出了涉及文件
- [ ] 生成了结构化文档
- [ ] 全程没有执行代码修改

## 注意事项

- 如果用户直接提供了完整信息，可以跳过部分步骤
- 如果信息不完整，持续追问直到清晰
- 最终文档由用户确认是否满足需求

## 错误案例（bad_eg）

| 错误操作 | 实际后果 | 正确做法 |
|---------|---------|---------|
| 直接猜测用户意图 | 用户不认可整理结果，需要重新整理 | 必须通过选项让用户确认 |
| 选项过于模板化 | 选项与项目无关，用户无法选择 | 应先列出项目实际文件作为选项 |
| 跳过步骤直接写文档 | 信息不完整，文档质量差 | 按 Step 顺序收集信息 |
| 执行了代码修改 | 违背"只整理不执行"原则 | 确认用户需要时才执行 |
| 一次问太多问题 | 用户疲劳，信息混乱 | 每次只问一个维度 |

## 我的犯错记录

| 错误操作 | 实际后果 | 正确做法 |
|---------|---------|---------|
| 创建 skill 时跳过 /sc:reflect | 缺少错误案例，模板不完整 | 必须先反思再写内容 |
| 选项用 `[列出常见效果]` 模板 | 选项不实用，用户需自行补充 | 应读取项目文件生成实际选项 |
