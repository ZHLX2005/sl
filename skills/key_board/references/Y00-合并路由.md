# Y00 — Y 序列元数据：合并路由

> **本文件不承载合并的执行细节**（那是 [[Y02-合并执行]] 的 4 阶段手册），只回答：**这个合并诉求从哪个成员进入？**

## 序列画像

| 项 | 值 |
| --- | --- |
| 序列代号 | B |
| 类别 | 合并——发现候选 → 动手执行 的两段式 |
| 成员 | Y01 合并审计 / Y02 合并执行 |
| 关键约束 | 审计只出报告不动手；执行必须经主流程确认"确需合并"（拆出去不行吗？） |

## 序列内路由（信号 → 成员）

| 用户信号 | 成员 | 边界提示 |
| --- | --- | --- |
| "扫一遍 / 哪些可合并 / 有没有重复"（未指定目标） | [[Y01-合并审计]] | 探索式：先报告后决策 |
| "把 A 合并进 B"（已指定目标） | [[Y02-合并执行]] | 跳过审计直接执行 |
| 审计报告某条被用户选中 | [[Y02-合并执行]] | 该条目按报告方案执行 |
| 只是想拆出去（不合并） | 不属于本序列 → [[X01-沉淀为ref]] | 拆 ≠ 合 |

## 顺序约束

探索式诉求**必须先 Y01 后 Y02**（报告是决策依据）；定向诉求可直达 Y02。Y01 报告是 Y02 的常见输入，但非硬依赖——用户点名合并时 Y02 可独立执行。
