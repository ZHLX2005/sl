# A03 — 内容同步（skill ↔ 真实代码对齐）

> **唯一思想：真实代码是唯一真相。** skill 里写的每条路径、类名、API，都必须在代码里找得到；代码变了，skill 必须跟上。skill 过期 = 下一个使用者按文档找全踩坑。
>
> **两种模式，一套流程**：增量和全量只是「对齐范围」不同——流程、验证、纪律完全一致，所以合为一个 ref，不建两个重复 SOP。
>
> | 模式 | 何时用 | 对齐范围 |
> | --- | --- | --- |
> | **增量** | 功能开发完成（提交/PR/merge 前）；"做完功能了更新 skill" | 仅本次 diff 涉及的 skill |
> | **全量** | 重构后 / 定期巡检；"skill 说的不对 / 找不到" / "扫一遍哪些过时了" | 单个或所有 skill |
>
> **与反思的边界已不存在**：本 ref 现在同时覆盖**事实层**（Step 1-5：路径/类名/API/依赖）与**经验层**（使用后的反思沉淀节）。功能开发后先事实后经验，同批完成。
>
> 结构问题（主文档臃肿、ref 未登记）不属于本 ref → [[A00-结构演化路由]] 对应成员。

## SOP（两种模式共用，5 步）

### Step 1: 确定对齐范围

```bash
# 增量模式：列出本次改动文件
git diff --name-only HEAD~1        # 提交前最近一次
git diff --name-only origin/main   # 功能分支 vs 主干
git status                          # 未提交的工作区

# 全量模式：直接指定对象
# 单个 skill（用户点名 / 用户报"说的不对"）或 <skills目录>/ 下全部
```

增量模式把改动文件按类型分类（这是后面判断的输入）：

| 改动类型 | 例子 | 影响 |
|---------|------|------|
| 新增文件 | 新增 `src/auth/oauth.py` | skill 可能没提到该模块 |
| 删除/移动 | `auth/login.py` 删掉/改名 | 旧路径变假引用 |
| 重命名 | `class UserModel` → `class Account` | 旧类名失效 |
| 签名/接口变化 | 参数、返回结构变化 | 使用示例失效 |
| 路由/配置字段变化 | 新增 `POST /api/v2/login`、env 改名 | 接口表/数据模型清单过期 |
| 新增依赖 | `requirements.txt` 加包 | 工具栈说明过期 |
| 新增子主题 | 引入新的错误处理模式 | 可能需要新建 ref |

### Step 2: 定位受影响的 skill 与引用

```bash
# 引用了本次改动文件/路径片段/旧类名的所有 skill（含 refs）
grep -rln "路径片段\|旧类名\|旧函数名" <skills目录>/

# 一键列出本次改动涉及的 skill（增量模式可选）
CHANGED=$(git diff --name-only HEAD~1)
for skill in <skills目录>/*/SKILL.md; do
  echo "$CHANGED" | while read f; do grep -l "$f" "$skill" 2>/dev/null && echo "↑ 受影响: $skill"; done
done
```

### Step 3: 逐项验证引用真实性（语言无关）

对每个命中的 skill，提取并验证三类引用——**这一步同时充当增量模式的"找出差异"和全量模式的"审计"**：

```bash
# 1. 文件路径引用：提取 + 验证存在
grep -oP '[\w/.\-]+\.[a-z]+' <skill文档路径> | while read f; do
  [ -f "$f" ] && echo "✅ $f" || echo "❌ $f"
done

# 2. 类/函数引用（按目标语言换关键字：class/def/fn/struct）
grep -rn "class UserModel\|def login" --include="*.py"

# 3. 相对 import 路径：从源文件目录解析后验证
python -c "
  import os.path
  resolved = os.path.normpath(os.path.join(os.path.dirname('path/to/source.py'), '../../some/module.py'))
  print(resolved, os.path.exists(resolved))
"
```

验证范围必须覆盖 `SKILL.md` **和所有 `references/*.md`**——只查主文档是最常见的漏网。

### Step 4: 修复（按优先级）

| 优先级 | 发现 | 处理 |
|--------|------|------|
| 🔴 P0 | 假引用（文件/类不存在） | 修正路径；目标已删除则删该节并全局替换旧名 |
| 🟡 P1 | 过时描述（接口已重构） | 更新描述、接口表、依赖矩阵匹配当前代码 |
| 🟢 P2 | 遗漏新模块/新模式 | 补充；独立子主题新建 ref（走 [[A01-沉淀为ref]] 规范 + 路由表登记） |

操作要点：

```bash
# 全局替换旧名（SKILL.md + 所有 refs）
grep -rln "src/auth/login\.py" <skills目录>/ | xargs sed -i 's|src/auth/login\.py|src/auth/oauth.py|g'
```

- 替换后**人工 review diff**，防误伤同名 token（变量名 `user_model` ≠ 类名 `UserModel`）
- 改接口表后**手动跑一遍**代码示例，确认可执行
- frontmatter 的 `description` 里若提着旧模块名，同步更新
- 发现不符**必须当场修正**——绝不放行已知的假引用（否则错误被放大）；用户报"说的不对"时先出分级清单再动手

### Step 5: 验证 + 提交

验证（必跑，两种模式同一份）：

```bash
# SKILL.md + 所有 refs 的路径引用全部存在
for doc in <skills目录>/<skill>/SKILL.md <skills目录>/<skill>/references/*.md; do
  grep -oP '[\w/.\-]+\.[a-z]+' "$doc" | while read f; do
    [ -f "$f" ] && echo "✅ $f" || echo "❌ $f"
  done
done
```

增量模式：skill 同步与代码改动**同一 PR**（或紧随 `chore: sync skills` commit），commit/PR 里标注同步了哪些 skill/ref——禁止过期 skill 留在 main 超过一个迭代。全量模式：输出审计报告（引用 | 状态 | 修复），留档。

## 经验层：使用 skill 后的反思沉淀

> 事实层对齐（Step 1-5）解决「skill 写错了」；本节解决「skill 没写到」——使用 skill 过程中踩的坑、发现的新模式。**先事实后经验**：功能开发后先走 Step 1-5，再走本节，同批进入 PR。
>
> **触发信号**："把这个经验记到 skill 里" / "记一下这个坑" / "保存这次调试经验" / "根据这次使用优化一下 skill"。

### 流程（4 步）

1. **回顾分类**：本次使用中——skill 说对了吗？发现新模式了吗？踩坑了吗？缺了什么关键步骤/上下文？
2. **转 good_eg / bad_eg**：每条踩坑**先记 bad_eg（含根因+修复代码），再加 good_eg（含正确做法示范）**，两者齐了才算"已反思"
3. **归属判定后写入**：特化子主题的经验 → 对应 ref；核心流程的经验 → SKILL.md 的错误案例表/正反案例；缺独立主题的 → 新建 ref（走 [[A01-沉淀为ref]] 规范 + 路由表登记）
4. **验证**：新加的引用 `test -f` / grep 确认存在；frontmatter 完整；`[[锚点]]` 有效

### bad_eg 最小结构（缺根因或修复 = 没记完）

错误做法 → 后果 → 根因分析 → 正确做法（代码）→ 预防方式。

## 完成后衔接

- 怀疑文档结构也有问题（场景内容混在主文档、ref 未登记）→ [[A01-沉淀为ref]]（存量补登记 / 批量模式二）或 [[A02-ref路由优化]]

## 常见坑点

| 坑 | 表现 | 预防 |
|----|------|------|
| 只查 SKILL.md 漏了 refs | ref 里的假引用继续存活 | 验证循环覆盖 `references/*.md` |
| sed 误伤同名变量 | `user_model` 变量被改成 `account` | 替换后 review diff |
| 文件被移动而非删除 | `test -f` 假但 grep 在别处能找到 | 先 grep 全局搜文件名再决定改路径还是删节 |
| 语言关键字混淆 | 用 `class` 搜 Go（Go 是 `struct`） | 按目标语言换 grep 关键字 |
| 类名大小写不匹配 | 写 `userModel` 实际 `UserModel` | grep 加 `-i` 或逐个核对 |

## AI 生成代码 Top错误事项(不超过5)

| 错误 | 后果 | 预防 |
| --- | --- | --- |
| 不读代码直接修文档 | 修完还是错的 | 先通读相关代码，代码是唯一真相 |
| 发现假引用不修正就放行 | 错误被后续使用者放大 | P0 当场修复或标注"已废弃" |
| 验证只覆盖 SKILL.md | ref 假引用漏网 | 循环必须含 `references/*.md` |
| 增量同步拆到代码 PR 外 | 过期 skill 留 main | 同一 PR 或紧随 chore commit |
| 检测标准写得太宽泛 | 无法执行 | 每条标准给具体命令/阈值 |
