# 结构优化 — 补引导与统一架构

> 两个低频场景共用本 ref（触发频率均 ⭐⭐ 以下）。拆 ref 相关动作（沉淀单主题、膨胀拆分）不在本 ref：走 [[沉淀为ref]]。

| 场景 | 频率 | 信号 |
| --- | --- | --- |
| B：添加 ref 加载引导 | ⭐ | 已有 references/ 但没写加载时机 |
| D：多 skill 统一 ref 架构 | ⭐ | 用户要求一批 skill 统一结构 |

## 场景 B：添加 ref 加载引导

**信号**：已有 `references/` 但 SKILL.md 没写加载时机——ref 存在但 AI 不知道什么时候读。

1. 列出现有 ref 文档
2. 在 SKILL.md 末尾加"何时读每个 ref"的引导段（索引表）
3. 用表格：`| ref | 何时读取 | 路径 |`

**引导段模板**：

```markdown
## 引用索引（按需加载）

| ref | 何时读取 | 路径 |
| --- | --- | --- |
| [[<ref-name>]] | [一句话加载时机，如"执行 xx 步骤时"] | references/<ref-name>.md |
```

**注意**：

- "何时读取"写**触发时机**（什么时候读），不写内容总结
- 如果正文流程中某一步强依赖某 ref，在那一步旁边也留 `[[锚点]]`，不要只在末尾索引表里出现
- B 场景不改正文内容，只加引导

## 场景 D：多 skill 统一 ref 架构

**信号**：用户要求一批 skill 统一结构（"统一所有 skill 的 ref 架构"）。

1. 选结构最完善的 skill 作模板
2. 把 ref 模式抽象成清单（锚点格式、索引表列、frontmatter 要求、加载引导写法）
3. 逐个 skill 应用
4. 每完成一个做最小验证（主题不重复、锚点齐全）

**统一时的角色分离红线**：统一过程中发现某 skill 主文档里场景内容和路由混杂，**顺手下沉**（迁移动作走 [[沉淀为ref]] 的 Step 1-5）——统一架构的目的正是让所有 skill 都达到"主文档 = 原则 + ref-map"的终态，而不是把混乱格式化成统一的混乱。

**批处理注意**：每完成一个 skill 报告一次进度；不要批量做完才汇报（用户可能要中途调整模板）。

## 两场景共同的校验

- [ ] 主文档无场景级内容残留（每章要么是原则、要么是路由）
- [ ] 每个 ref 在 SKILL.md 有 `[[锚点]]` + 索引表登记
- [ ] 每条索引写的是"何时读取"而非内容总结
- [ ] 前置 skill（其他已存在 skill）未受影响
- [ ] 核心流程/触发条件未变

## AI 生成代码 Top错误事项(不超过5)

| 错误 | 后果 | 预防 |
|---|---|---|
| "何时读取"写成内容总结 | AI 仍不知道什么时候读 | 每条索引写触发时机 |
| 补引导时顺手改正文流程 | 越权修改核心流程 | B 场景只加引导，正文一字不动 |
| 统一架构时把混乱格式化成统一的混乱 | 治标不治本 | 发现场景内容混在主文档，顺手下沉到 ref |
| 批量处理做完才汇报 | 用户中途想调整模板已来不及 | 每完成一个 skill 报告一次进度 |
