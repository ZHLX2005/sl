# B05-multi-line-cli-input — 多行 CLI 输入的 heredoc 处理方案

> **本 ref 是扩展方案**（与 B04 同性质，非重操作）。参考实现用占位符 `xxx` 指代——
> 本 skill 是可交付的通用规范，不指向任何内部项目；落地细节以你自己的项目为准。

## 加载时机

- 给 CLI 加一个需要接受**多行文本**的参数时（任务描述、长规范、prompt 模板）
- 用户报告「传多行内容后后面的 flag 丢了 / 内容只剩第一行」时
- AI 生成的 heredoc 命令格式错误、执行失败或静默出错时

## 一、平台根因：多行参数跨 exec 边界会被切开（实测）

**现象**（Windows / Git Bash 实测复现）：

```
命令：xxx loop start "$P" --max-iterations 7     # P = "第一行\n第二行"
实际 argv = ['loop', 'start', '第一行']           ← 只剩第一行
argv 个数 9 → 5，--max-iterations / --session-id 全部丢失
```

**后果比"内容截断"严重得多**：后面的 flag 被挤成位置参数或直接消失，
程序**不报错**、用默认值继续跑——上限、开关等关键参数静默变成默认值。

**结论**：多行内容**绝不当命令行参数传**。走 stdin，让它根本不经过 argv。

## 二、实现方案：`<参数>` 传 `-`，从 stdin 读

### CLI 形状

```
xxx <cmd> - --flag value <<'EOF'
多行内容
第二行
EOF
```

### 实现要点（从真实落地提炼）

1. **参数值 === `'-'` 时切到 stdin**——`-` 是约定俗成的"从标准输入读"记号；
   不要发明 `--stdin` 之类的新 flag
2. **复用已有的 stdin 读取 helper**（项目里 hook 落点通常已有一个带
   EOF 竞速超时的读取函数），不要重新实现
3. **超时放宽**：hook 落点的 1s deadline 对 heredoc 太紧；多行输入场景给
   10s 量级（heredoc/管道都是毫秒级到达，上限只为「stdin 挂着不关」兜底）
4. **trim 尾部换行**：heredoc 必带结尾换行，去掉；首尾空白对文本内容无意义
5. **空 stdin 报 `INVALID_INPUT` 并给出 heredoc 用法示例**——**绝不静默建出
   空内容的记录**
6. **stdout 输出确认信息时不要回显全文**——多行内容可能很长，确认行 +
   状态落点即可；内容已在程序状态里，agent/用户要看自有渠道

### 与编辑类命令的组合

同一条命令若支持「改已有记录的文本字段」，**同样支持 `-`**——多行场景
不止出现在创建时。改文本字段的版本语义（归档旧值、升版号）不受影响。

## 三、AI 写 heredoc 的四种实测错误（按危害排序）

> 以下每一种都**实测复现过后果**，不是理论推演。写文档/示例时按
> 「成功模板在前、错误对照在后」排布——AI 优先模仿它看到的第一个形状。

### ✅ 成功模板（文档里放最前）

```bash
xxx <cmd> - --flag value --another-flag v <<'EOF'
多行内容第一行
第二行

第四行（上一行是空行）
EOF
```

四要素：**`-` 占位**、**flag 全在 heredoc 之前**、**`<<'EOF'` 带引号**、
**EOF 顶格在行首**。

### ❌ 1. 定界符不加引号 `<<EOF` —— 数据静默改写 / 命令执行

实测：内容里的 `$100` 被展开成 `00`（positional param）、反引号里的命令
**真的被执行了**。任务规范本要传递的文本被 shell 当代码跑了。

→ **必须 `<<'EOF'`**（带引号 = 原样传入，零展开）。

### ❌ 2. flag 写在 heredoc 之后 —— 关键参数静默丢失

```
xxx <cmd> - --flag v <<'EOF'
内容
EOF
--another-flag x     ← 这行被 shell 当独立命令执行：command not found
```

循环/记录照样创建，但参数用默认值——**完全无报错**。最阴险的失败模式。

→ flag 必须全在 `<<'EOF'` 之前。

### ❌ 3. 定界符被缩进 —— 吞掉后续所有命令文本

`EOF` 前有空格时 bash 警告 `delimited by end-of-file`，然后**把脚本里后续
所有命令的文本全当内容吞掉**——实测连 `rm -rf` 清理命令的字符串都进了内容。
记录照样创建，无人察觉。

→ EOF 必须顶格；要缩进用 `<<-EOF` + **Tab**（空格无效）。

### ❌ 4. 忘记写 `-` —— 安全（立刻报错）

CLI 报「缺少必填参数」退出。这是**安全失败**——不会建出坏记录，列在这里
只为与前三条对照（前三条都是静默的，只有这条会喊）。

### 文档写法提醒（给维护本 skill 的人）

在**自己的 skill** 里更新这条规范时：成功模板放章节最前、给完整可复制的
命令（含全部 flag）；错误对照放后面，每条附实测后果。AI 写 heredoc 时
优先拷贝第一个形状——第一个形状必须是正确的。

## 四、测试要点

- **子进程隔离**：`spawnSync(process.execPath, [bin, ...args], { input })`
  ——用 `input` 喂 stdin，**不经过 shell**，正好测 CLI 的 stdin 路径本身
- **Windows + Volta 坑**：改 `USERPROFILE` 会让 Volta shim 报
  `Could not determine LocalAppData`——子进程必须用 `process.execPath`
  （真实 node 二进制）而非 PATH 上的 shim
- **状态目录隔离**：给子进程自定义 `USERPROFILE/HOME`，让状态文件落在
  临时目录；断言时用与主进程一致的哈希算法定位子进程的状态文件
- **覆盖面**：多行内容逐字节保留（含空行）/ flag 不被吞（数一遍 argv 该在的
  都在）/ 空 stdin 报错不建记录 / 编辑路径同样支持 `-` 且旧值归档
- **资产根注入**：需要伪造包内资产时用环境变量覆盖资产根目录
  （如 `XXX_ASSETS_ROOT`），**在调用时读取而非模块加载时**——否则测试的
  import 顺序决定行为
