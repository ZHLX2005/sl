# M01 — 质检：内容审计 + `.QUALITY-AUDIT.md` 留档

## 这一篇解决什么

「这个 skill 说的事还成立吗」「哪些段落已经过时 / 没依据」「写完的 ref 怎么验收」「多轮质检的历史在哪看」。
输出两样东西：**修好的 ref 文档** + **一份可回溯的 `.QUALITY-AUDIT.md`**。

## 适用 / 不适用

| 适用 | 不适用 |
| --- | --- |
| 全量质检某个 skill 的 ref（含跨 ref 一致性） | 单条事实差异当场修复 → 走 [[X01-ref体系SOP]] §3.1 全量巡检 |
| 需要留档、需要多轮审计记录 | 只想拆 ref / 改编号 → 走 [[X01-ref体系SOP]] §2 / §1.5 |
| 需要判断「这段该删还是该改」并给依据 | 改应用代码 / 修 bug → 登记 follow-up，不在本流程里动 |

**与 X01 §3.1 全量巡检的边界**：§3.1 逐条对比代码、**当场修**事实层偏差，不留档；
M01 做整体判断（该不该存在、有没有依据、写法是否统一），**留档**，源码问题只提不改。
两者可同批执行：先 §3.1 修事实，再 M01 判结构与留存。

## 前置条件

- 目标 skill 目录可读；有 `references/`（没有 ref 的 skill 只做主文档与触发描述，跳过 ref 相关步骤）。
- **先判作用域**：目标 skill 是**通用级**（不指向任何真实路径 / 类名 / API）→ 跳过「与代码一致」取证，只做结构、写法、错误案例与留存检查；是**项目级** → 才需要下面的代码库。
- 项目级 skill 需能读到对应的**真实代码库**（否则「与代码一致」这一步只能记 `unverifiable`，不许假装查过）。
- 不需要网络与 key；需要写权限才能落 `.QUALITY-AUDIT.md`（只读目标 → 只出报告，见 §回退）。

## 执行流程（6 步）

1. **建基线**：读主 `SKILL.md` → 读 `references/` 全部文件清单 → 若有历史 `.QUALITY-AUDIT.md`，先读最后一节，继承未解决的 follow-up。
2. **定范围**：按序列划分检查单元（X / Y / M，或按 ref 主题分组）；ref ≤ 4 篇时单线程顺序检查。
3. **逐篇取证**（**仅项目级 skill**）：对每篇 ref 的每个"事实句"（路径、类名、函数名、命令、配置键、数字、版本），到真实代码/文档里核一次；核不到就标 `unverifiable`，**不许保留"看起来像真的"的句子**。通用级 skill 跳过本步。
4. **判定处置**（见下「判定标准」）：保留 / 改写 / 删除 / 拆出成新 ref。
5. **收敛错误案例 + 判龄**：把本篇/本 skill 的错误案例重排为 Top5（规则见下）；同时按「时间 / 复核于」判龄——
   超过 12 个月未复核、未再复现的先判后删，命中「失效条件」的直接删，没写日期与时机的补齐或删除。
6. **落档**：写 `.QUALITY-AUDIT.md` 新增一节，列出本轮改了什么、删了哪些过期记录、没解决什么；**追加不覆盖**。

### subagent 分工（大型 skill / ref ≥ 8 篇时）

- 一个序列一个 subagent（X / Y / M 各自一个），或按 ref 主题均分（每包 3–5 篇）。
- 每个 subagent 的输入必须给全：目标 skill 路径、真实代码库路径、**本轮的判定标准与输出格式**、以及"只提不改代码"的红线。
- 输出契约（缺一项就打回）：
  1. 逐篇结论表：`ref | 事实句数 | 核实数 | 删除数 | 改写数 | unverifiable 数`
  2. 删除清单：`文件:行 → 删的原句 → 删除依据`
  3. follow-up 清单：`源码问题 → 证据（文件:行）→ 建议动作`
  4. 未完成项：为什么没核（无代码库 / 无权限 / 目标不存在）
- 主 agent 只汇总与裁决冲突，不重复逐篇取证。

## 判定标准（什么该删、什么该留）

| 段落状态 | 处置 | 判据 |
| --- | --- | --- |
| 有真实代码/文档支撑，且与当前版本一致（**项目级**） | **保留** | 能给出 `文件:行` 或命令回显 |
| 事实仍成立但写法与其它 ref 不一致 | **改写** | 统一标题层级、统一"命令 / 说明"格式 |
| 无任何依据、也无法核实的推测 | **删除** | 说不出"这句从哪来"就删 |
| 曾经成立、现已失效（版本/路径/接口变更） | **删除或改写** | 有 changelog / 代码现状佐证 |
| 一个 ref 混了 2 个以上独立主题 | **拆出** | 按 [[X01-ref体系SOP]] §2 拆，拆完登记路由表 |
| 迁移期/兼容期的一次性说明，SOP 已稳定 | **删除** | 只服务过渡，长期是噪声 |
| 源码 bug / 设计缺陷 | **只登记 follow-up** | 询问"改 skill 还是改代码"，不在本文档动手 |
| 教训记录没有日期或没有触发时机 | **补齐或删除** | 能确认就补 `YYYY-MM-DD｜命令+版本+环境`；确认不了就删（无法判龄的记录等于永久噪声） |
| 教训记录超过 12 个月未复核、也未再复现 | **先判后删** | 仍成立 → 把「复核于」更新为当天；不成立 → 删 |

**数字与版本必须来自实读**：条数、字节数、版本号、函数签名——引用二手文章里的数字一律视为无据。

## 错误案例 Top5 规则

- 收录条件（同时满足）：**真实发生过**、**能一句话说清根因**、**有可执行的预防动作**、**带日期与触发时机**。
- 写法：`YYYY-MM-DD｜时机` 作标题，正文 `症状 → 根因 → 预防`，三段各一句；不写故事、不写"要注意"这类空话。
- 排序：按"发生频次 × 后果严重度"降序，取前 5；同分时取**更近发生**的（新记录更可能仍成立）。
- 淘汰：新案例进榜时，把最弱的一条移出（不是让榜单变长）；失效的（对应流程已删）直接移除；
  **超过 12 个月未复核且未再复现**的，本轮质检优先判它——留不住就删。
- 位置：错误案例只在**一处**维护（目标 skill 的专属 ref 或主文档的"易错"表），别在多篇里重复列同一案例。

## `.QUALITY-AUDIT.md` 模板

放在**被质检 skill 的根目录**（与 `SKILL.md` 同级），一节一轮、只追加：

```markdown
## 质检 YYYY-MM-DD

**审计基线**
- 目标：<skill 名>（ref N 篇 / 主文档 M 行）
- 代码基线：<仓库> @ <commit 或版本>（无代码库则写 unverifiable）
- 本轮范围：<X 序列 / 全量 / 指定 ref>

**逐序列审计记录**
| ref | 事实句 | 核实 | 删除 | 改写 | unverifiable |
| --- | --- | --- | --- | --- | --- |

**本轮已落实的文档修正**
- <文件:行>：<改前 → 改后>（依据：<代码位置 / 命令回显>）

**本轮删除的过期记录（教训判龄）**
- `YYYY-MM-DD｜时机`：删除原因（>12 个月未复核 / 命中失效条件 / 无日期无法判龄）

**未解决的源码级 follow-up**
- [ ] <问题>（证据：<文件:行>）→ 建议：改代码 / 改 skill（待确认）
```

## 完成检查清单

- [ ] `references/` 每篇都过了判定表，没有"没核就保留"的段落
- [ ] 所有删除项在审计档里能查到原句与依据
- [ ] 错误案例只有一处维护，且 ≤ 5 条
- [ ] 每条教训都带 `YYYY-MM-DD｜命令 + 版本 + 环境`，缺失的已补齐或删除
- [ ] 超过 12 个月未复核的记录已判龄（删掉，或把「复核于」更新为当天）
- [ ] 本轮删掉的过期记录已在审计档里列出（删了什么、为什么）
- [ ] 跨 ref 重复内容已合并到唯一出处（其余位置只留指针）
- [ ] `.QUALITY-AUDIT.md` 新增一节，未覆盖历史
- [ ] 源码级问题全部登记为 follow-up，未改应用代码
- [ ] 质检后主文档没有变长（新增内容落在 ref 里）

## 坑

| 坑 | 正确做法 |
| --- | --- |
| 把"读起来顺"当成"事实成立" | 每个事实句都要有 `文件:行` 或命令回显 |
| 质检完顺手把主文档写胖 | 结论写 ref，主文档只留指针 |
| 覆盖上一轮 `.QUALITY-AUDIT.md` | 追加新节，历史留痕 |
| 目标 skill 只读还硬写 | 只出报告与 diff 描述，落盘前先要写权限 |
| 无代码库却声称"已核对代码" | 标 `unverifiable`，并在完成项里写明原因 |
| 教训只写"上次出过事" | 写绝对日期 + 命令 + 版本 + 环境；没有这三样，一年后没人能判断该不该删 |
| 只增不删，错误案例越积越多 | 判龄：12 个月未复核先判后删；命中失效条件立即删 |
| subagent 各自为政、口径不一 | 统一判定标准与输出契约再分发，主 agent 汇总裁决 |
