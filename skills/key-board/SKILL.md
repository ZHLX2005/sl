# Key Board — Skill 生命周期路由器

## Purpose

让 skill 体系随使用持续演化，而不是每次对话都新造一个 skill。只做结构与内容治理（拆分 / 合并 / 同步 / 创建 / 质检），不改代码、不评效果。

> 本 skill 自身遵守下述标准：**唯一 SKILL.md 作 ref-map**，**7 篇 ref 全在 `references/`、序列命名**。

## 强制标准（所有 skill 一律如此）

1. **单 SKILL.md 作 ref-map**：只放 原则 / 路由表 / 序列总览 / 检查清单；场景内容全在 `references/`；不另起根级 README / 指南 / INDEX。**落在哪都一样**——平台目录（`.claude/` / `.agent/` / `.workbuddy/`…）、项目自带静态 skill 资源、面向开发者还是终端用户，架构一律相同。
2. **references/ 全部序列命名**：`<序列字母><两位序号>-<名称>.md`，从第一篇起就编号，无数量门槛 → [[X01-ref体系SOP]] §1。
3. **ref 只写 SOP**：步骤 / 判定 / 正反例；不写背景知识、百科、术语科普、经验流水账。
4. **场景一到就建 ref**：能补进既有 ref 就补，主题独立才新建；主文档不随场景变多而变厚。
5. **写内容前过作用域闸** → [[X02-产物作用域]]（判内容作用域 通用级/项目级 + 判载体形态 落在哪）。

## 路由优先级（最重要）

**先扩展现有 ref，无相关主题才创建新 skill。**

1. 信号是否命中上表 X01 / X02 / M01 / Y01 / Y02 任一？
   - **是** → 加载对应 ref 走 SOP；不确定进序列哪个成员时先读该序列的 `X00` 元数据 ref。
   - **否** → 第 2 步。
2. 是否需要新增 ref 承载这个场景？
   - **是** → 走 [[X01-ref体系SOP]] §2（新建 / 扩展既有 ref 树），代号按 §1 分配。
   - **否**（全新独立主题） → 走创建：[[X01-ref体系SOP]] §4。

> 新增 ref 是「体系内演化」（低成本），创建新 skill 是「体系外扩张」（高成本）。先内后外。

## 平面扩展原则

- 主文档只含：强制标准 + 路由表 + 序列总览 + 路由优先级 + 原则 + 主流程骨架 + 检查清单。场景级内容一律在 references/。
- 扩展模式固定：新场景 → 新建 ref + 路由表加一行，主文档不加章节、不长胖。
- ref 数量可无限扩展，主文档行数不随场景数增长。

## 核心原则

| 文档 | 角色 | 只放 | 不放 |
| --- | --- | --- | --- |
| 主 SKILL.md | ref-map | 强制标准、路由表、序列总览、路由优先级、原则、骨架、检查清单 | 任何场景级细节 |
| references/X00-*.md | 序列元数据 | 序列内信号→成员路由、成员边界、升级路径 | 动作 SOP |
| references/<XN>-<名>.md | 动作 SOP | 某动作的完整 SOP、示例、正反例、判定细节 | 通用原则 |

**产出物作用域**（横切，写内容前必过）：通用级零项目上下文，项目级用当前项目真实值——判定与红线见 [[X02-产物作用域]]。

**边界**：不改其他 skill 的核心流程/触发条件（除非用户授权）；不动 skill 的代码实现；不评效果（交 skill-creator）。

## Prerequisites

纯本地文件操作：无网络、无 API key、无脚本依赖；需目标 skill 的 `references/` 可读，写操作另需写权限。

## Limitations

只搬文档结构、只写文档内容；不执行目标 skill、不改触发条件、不评效果、不处理跨机器分发。

## Instructions：主流程骨架（5 步）

1. **识别作用域**：用户信号是什么？目标对象是哪个 skill（创建时无对象）？
2. **路由判定**：查路由表 → 命中则走第 3 步，未命中先走第 4 步评估优先级。
3. **设计方案**：加载对应 ref，出方案（ref 名称、路径、加载时机、为何独立主题）；先声明产出物作用域。
4. **执行**：按 ref 的 SOP 执行；共同骨架 = 迁移内容 → 原位置留 `[[锚点]]` + 一句总结 → 路由表登记；下沉必须彻底。
5. **校验**：对照 ref 内的检查清单逐项过。

## Troubleshooting：路由失败与回退

| 情形 | 处置 |
| --- | --- |
| 一句话命中两篇 ref | 优先级：改结构 > 改编号 > 改内容；仍不确定就把候选 ref 的「适用 / 不适用」各读一遍 |
| 目标 ref 缺失 / `[[锚点]]` 断链 | 在 `references/` 找同名文件；没有就补建并立即在路由表登记，不允许静默跳过 |
| 路由到「创建」但已有相近 skill | 回到路由优先级第 2 步，先扩展现有 ref；确认无主题再创建 |
| 目标 skill 只读 / 不在本机 | 只出方案与改动清单，不落盘 |

## 成功标准检查清单

- [ ] 路由优先级被遵守（先扩展 ref，无相关主题才创建）
- [ ] 主 SKILL.md 只作 ref-map，无场景级内容残留
- [ ] 所有 ref 在路由表登记，写明"何时读取"；`[[ref-name]]` 与文件名一一对应
- [ ] 命名符合序列规则（`<代号>-<名称>.md`），序列总览在明细表之前
- [ ] 目标 skill 的核心流程/触发条件未变（除非用户授权）
- [ ] 产出物作用域已声明（见 [[X02-产物作用域]]）
- [ ] 没有空 ref 文档；用户确认了拆分方案（如未明确授权）

## 何时**不**触发本 skill

- 用户想改 skill 的代码/实现 → 不管代码
- 用户想优化触发描述 / 评估 skill 效果 → `skill-creator`
- 目标 skill 无独立主题且不需创建 → 不要硬拆，劝退

## 与其他 skill 的协作

```
key-board        →  skill 生命周期管理（路由 + 7 ref SOP，3 序列：X 结构演化与维护 / Y 合并 / M 质检）
skill-creator    →  评估/优化/打包 skill (质量保障)
```

职责不重叠：key-board 是"路由器 + 演化执行器"，skill-creator 是"质量评估与优化器"。
