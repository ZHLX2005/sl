# Browser Harness — 交付要求

本 skill 只规定浏览器任务的**交付契约**，不规定具体实现。操作方法（连接、导航、提取、脚本写法、坑点）以 /browser-harness skill 为准，此处不重复。

## 铁律

1. **自己调用** — 先加载 `/browser-harness` 获取操作方法，然后所有浏览器操作自己执行。禁止问用户"Chrome 打开了吗"，禁止让用户代做任何浏览器操作（包括启动浏览器——`ensure_daemon()` 会自动处理）。
2. **端到端闭环** — 连接、执行、产出、验证全部自己完成。任务以"真实浏览器里验证过的结果"为终点，不以"代码写完"为终点。
3. **绝对验证** — 验证依据是真实浏览器状态。代码审查、接口返回 200、"应该可以了"都不算验证。
4. **终验必须是真实 CDP 实测** — 最后一步必须是通过 CDP 连接真实浏览器（常见端口 `127.0.0.1:9222`）取得的证据：DOM 断言输出、截图、实际提取数据。没有终验证据，不得宣布任务完成。
5. **交付结果本身** — 交付物是数据文件、实测记录。禁止把单独一个 URL 当交付物让用户自己点开看；禁止只说"已经修改 / 你试试"。

## 终验要求

最后一步的验证按层级衡量（CDP 端口常见为 `127.0.0.1:9222`）：

| 层级 | 要求 | 通过标准 |
| ---- | ---- | -------- |
| **连接层** | 能通过 CDP 连上真实浏览器 | 返回真实 Browser/版本信息 |
| **状态层** | 断言目标状态：元素渲染、数据出现、行为生效 | 断言为真且有真实输出。**任何任务不可跳过** |
| **证据层** | 截图或数据落盘 | 文件存在、内容非空 |
| **回归层** | 按用户原始场景完整复测 | 全程无报错，终态符合预期。改动/修复类任务必须做 |

## 交付要求

交付 = 结果产物 + 终验证据。

| 不合格交付 | 为什么不合格 | 合格替代 |
| ---------- | ------------ | -------- |
| "这是地址：http://localhost:5173，你看下效果" | 把终验推给用户 | 自己打开页面断言关键元素渲染，附断言输出/截图 |
| "已经修改完成" | 无证据的口头完成 | 附改动后真实浏览器的复测记录（DOM 状态/页面行为实测输出） |
| "脚本写好了，你跑一下" | 没跑通就交付 | 自己执行直到通过，交付真实运行输出 |
| "接口返回 200，说明没问题" | 未覆盖 JS 渲染与交互 | 最后一步在真实浏览器里复测完整场景 |

URL 只能作为**已被实测过的证据**出现，不能是让用户自己去看的交付物。
